# Flujo de Trabajo Colaborativo con GitHub Desktop

Este proyecto tiene como objetivo la práctica de un flujo de trabajo colaborativo en GitHub Desktop, incluyendo ramas, revisiones de código, resolución de conflictos y gestión de cambios.

## 📌 Objetivos
1. **Configuración de un flujo de trabajo colaborativo:** Creación de un entorno de trabajo con ramas, revisiones y merges.
2. **Resolución de conflictos:** Aprender a gestionar y resolver conflictos en GitHub Desktop.
3. **Deshacer el trabajo (hard reset):** Recuperar versiones previas del repositorio y revertir cambios.
4. **Presentación del trabajo:** Documentación y presentación del proyecto.

---

## 🛠️ Configuración de un Flujo de Trabajo Colaborativo
1. Configurar un repositorio inicial en **GitHub** desde **GitHub Desktop**.
2. Crear ramas de trabajo (`feature branches`) separadas para cada colaborador, manteniendo libre la rama `main`.
3. Trabajar en funcionalidades distintas y realizar commits regularmente.
4. Realizar un merge conjunto a la rama `main` después de la revisión y aprobación.

---

## ⚔️ Resolución de Conflictos
1. Cada integrante edita la misma parte de un archivo en ramas separadas.
2. Subir los cambios al repositorio remoto.
3. Intentar hacer merge de una rama en otra.
4. Resolver manualmente los conflictos utilizando las herramientas de **GitHub Desktop**.

---

## ⏪ Deshacer el Trabajo (Hard Reset)
1. Revertir modificaciones para recuperar la última versión guardada en el repositorio.
2. **Eliminar** completamente un proyecto local y volver a clonarlo desde el repositorio remoto.
3. Crear un nuevo commit y posteriormente **revertirlo** antes de subirlo.
4. Crear dos commits, subirlos al repositorio con `push`, y revertirlos en una única revisión nueva.
5. Revertir la rama `main` a su segunda revisión, eliminando todos los cambios posteriores.
